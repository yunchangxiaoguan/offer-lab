# Offer 来了 · 求职练习室

学生粘贴基本信息和 3–5 个项目，点击一次即可依次生成中文简历、五点面试稿和十八点深挖稿。信息不足时，工作台保存草稿，指出需要补充的项目、问题和可查的资料。拿到可投递简历后，可以从自己的项目出题。公共题库随时可练。

## 在 Windows 打开

下载或解压整个项目，双击 **打开_Offer来了.bat**，浏览器会打开学生工作台。第一次使用需要 Python 3.10 或更高版本。如果电脑缺少 Word 和 PDF 导出组件，启动窗口会询问是否下载。选 Y 后，组件安装在本目录的 `.venv` 中。工作台运行时保留启动窗口，用完关闭即可。

学生入口默认使用本机端口 8736，教师入口使用 8737。也可以在项目目录运行 `python -m pip install -r requirements.txt`，再运行 `python app.py --open`。用 `python app.py --check` 可检查本机能否打开首页并读取题库。

## 学生怎样用

1. 在「我的求职材料」粘贴基本信息。建议写清求职方向、教育、工作经历，以及投递时需要的联系方式。
2. 把 3–5 个项目一起粘贴。每个项目用“项目一：名称”起头。写清谁在什么场景遇到问题、本人负责哪一部分、怎样验证、实际交付了什么。只有本地演示结果，就写本地演示。系统按目标岗位选择标准，AI 应用开发班会核对 Agent、RAG、微调、部署和测试分别做过什么。投其他岗位时可选择实际岗位标准。
3. 点击「生成三份材料」。资料不齐也可先保存。每轮先看最多三组补充问题，可以补事实、说明查不到的记录，或改清个人和团队分工。保存后再生成。提交完整后，简历按最终 Word 和 PDF 核对，PDF 为 2–3 页。五点稿含自我介绍、主项目短讲、第二项目备讲和至少 20 道带回答的追问。十八点稿沿用同一份简历和五点稿，含 18 个考点、逐层追答、指标和异常案例练习，以及 7 条主线的 15／60／120 秒讲法。具体用时由学生朗读验证。
4. 在「模拟面试」选择具体的简历版本，点「生成专属题」后开始作答。一场最多六题，可以中途返回，接着上次的进度继续。答题后可以看正确选项、理由、口述示范和下一问。错题进入「错题复习」，重答正确后从待复习列表移出。

公共题库无需先建简历。先选面试环节，再按“技术专题 → 子类”收窄范围，也可以直接搜词。比如“系统架构与技术选型 → Agent 智能体 → LangGraph”用于准备框架选型。“RAG 知识库 → 文本切块与父子分块”聚焦切块策略。“RAG 知识库 → 缓存与失效”与“模型部署与运行 → 显存、量化与 KV Cache”分别覆盖知识库结果复用和模型推理两个问题。同一道题可从关联子类找到，作答记录共用。

### 版本、修订与恢复

每份稿子显示它依据的资料和简历版本。可以下载 Word、PDF、Markdown，也可编辑正文另存新版本。比如把“本地验证”改成“生产上线”，系统会重新对照原项目。要补一个真实的新结果，先改学生资料，再生成同版的三份材料。

升级前的稿件和从备份恢复的稿件会标为历史版本。打开原文，先复核简历，再复核或生成对应的五点稿、十八点稿。旧稿缺少依据版本时，可从合格简历生成新稿。模型回复中断后，回到同一份资料、使用相同生成方式重试，已确认的面试稿段落可以接续。草稿和历史稿的下载文件名会标出状态。

首版内置 **308 道可练选择题**，可从 9 个面试环节、8 个技术专题、46 个子类查找。其中 20 道从面试记录提炼考点，重新编写了选项与答案。迁移表保留指定版全部 550 个旧编号，规范化同文后有 457 组。重复问法或考查同一判断的旧题可以指向同一张练习卡。输入旧编号、上游题号或“旧题 492”即可找到对应练习。

## 老师怎样更新题库

1. 双击 **教师题库维护.bat**。用自动打开的浏览器页进入维护界面。教师资格随本次本机启动生效。
2. 粘贴转写，或选择一个或多个 UTF-8 编码的 TXT、Markdown 文件。尽量保留“面试官”“候选人”等发言人标记。点击「整理本批」查看新题、已有题的补充问法、待核对片段。
3. 展开题卡核对来源提问、题干、四个选项、每个选项的理由、口述答案和追问。标错说话人、没说清条件的片段，需要对照原记录。老师可以手工补成选择题。对说话人明确、含义足够清楚的待处理提问，配置了模型的电脑也可点「用在线模型整理待处理提问」。长转写会分组处理，部分失败时保留已经编好的题。
4. 勾选已经核对的条目并发布。本机题库及新开的模拟场次即可使用。可以回看实际发布的条目，按发布顺序从最近一批开始撤回。
5. 给其他电脑更新时，导出该批的题库更新包。在对方电脑用教师入口载入、核对并发布。涉及早期新增题的后续补充问法，需要先导入包含该题的前一批。已作答的场次保留当时的题面和答案。

## 两种生成方式与数据保存

默认在本机提取事实，按固定结构组织材料、匹配题目。需要自由改写或增加模型出题时，可以在启动前配置系统环境变量 `DEEPSEEK_API_KEY` 或 `OPENAI_API_KEY`，然后在对应操作处勾选「使用在线模型」。同时配置时使用 DeepSeek。自定义同一服务的模型名可设置 `OFFER_MODEL`。

开启在线生成简历或稿件时，应用会向所选模型服务发送基本信息和项目事实，先处理常见电话、邮箱和姓名字段。出专属题时会发送所选简历中的项目名称和证据原句。在线整理转写时会发送待处理的提问。粘贴前请自行处理项目原句里不宜提供给服务方的内容。核对简历和口述稿时，以本人实际分工、上线情况和指标来源为准。

学生记录和教师批次保存在本机 `%LOCALAPPDATA%\OfferLab\workspace.sqlite3`。可以在启动前用 `OFFER_DATA_DIR` 指定其他私有目录。同一浏览器会接续自己的资料；换人或换设备前，从「备份资料与切换学生」下载私有备份，之后可在同一菜单恢复。备份包含简历和练习记录，请只交给本人。教师题库更新包与学生备份是两种不同的文件。

## 模块与维护分工

| 负责人 | 模块 | 交接与验收 |
| --- | --- | --- |
| 总控 | 学生资料、版本、桌面入口、集成 | 把同一份资料串到三份成品、专属题和模拟场次，用两套独立浏览器记录核验隔离、备份及恢复。 |
| 简历 Agent | 资料补问、简历生成和导出核对 | 维护班级与岗位标准、项目依据、书面表达和最终下载文件。 |
| 面试稿 Agent | 五点稿与十八点稿 | 维护讲稿结构、口述表达、分段恢复、主项目和版本一致性。 |
| 题库 Agent | 公共选择题、分类、旧题迁移 | 维护面试环节、技术专题、子类和搜索别名。每个旧题号在迁移表中有去向，每道发布题有答案、逐项理由和口述追答。 |
| 练习与教师维护 Agent | 专属题、模拟面试、转写入库 | 专属题引用指定简历。教师先审核再发布，学生端同步读取本机公共题库，历史作答保留快照。 |

材料生成与维护可查阅[简历生成规则](skills/offer-resume/SKILL.md)、[面试稿规则](skills/offer-interview-scripts/SKILL.md)和[中文自然表达规则](skills/humanizer-zh/SKILL.md)。技术目录在[分类与别名](bank/taxonomy.json)，旧题编号的去向在[迁移表](bank/migration.json)。

开发者可运行 `python -m unittest discover -s tests` 核验规则、题库和教师发布流程。已有 Playwright 和桌面 Chromium 时，可运行 `python tests/browser_flow.py` 验证学生端实际操作。
