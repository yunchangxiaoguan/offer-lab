# 为一个学生生成简历

直接交付该生的简历正文。学生只需提供基本信息和项目，自我评价、旧简历、招聘 JD 都可省略。遇到资料缺口，先写有依据的内容，给学生的核对问题另放。网页要求只返回正文时省去核对问题。

## 选材与排序

先确定求职方向和每个项目的使用者、业务动作、本人负责的环节、交付物和验证依据。公司是雇主、客户、平台渠道还是公开案例，沿用材料已确认的关系。学历与学位分开，实际开发年限与毕业年数分开。

大模型应用岗位在有对应证据时先排 Agent，再排 RAG，随后给出其他模型应用及工程能力。把已实现的 Harness、Skills 和工具接入写进对应 Agent 能力，不为缺证据的技能占位。其他方向优先匹配岗位和本人职责。常规投递版选三个完整项目，明确有三年以上相关开发经验时可写四至五个，最多五个；保留原始输入供后续另选。岗位或学生另有明确选择时按指定范围。

## 写法与交付

姓名、求职信息、专业技能、实际工作与教育经历、项目经历依次成篇。工作按时间倒序，只有明确给出的履历条目才写。首屏让招聘者看到主项目及本人贡献。项目标题保留源材料中的项目名与时间。

每个项目先说谁遇到了什么问题，再写本人用什么方法解决哪一环、团队接手哪一环、形成了什么交付。采用自然的短段或要点。主项目优先写清有据可查的关键动作，备选项目简写。每项技能能在对应项目里解释具体用途。不得从团队技术栈推断个人熟练度。

每个项目优先用一至两项有口径的质量、效率、成本或稳定性指标说明效果。保留基线、样本、范围和原有确定程度；百分点与百分比区分。缺可靠结果时只陈述交付和使用边界。规模、模块数量、演示数据、模拟成绩均不可改为真实效益。删除无事实支持的空泛优势。以正常字号按二至三页组织。正文不插入技术评估、打分、营销宣传或模拟数字。

收到增量信息时，只调整受影响的技能、项目职责或成果。若“同事负责重排，我负责召回”是最新材料，就收回旧稿中重排归属。导出或交接前逐项对照个人名字、教育、客户关系、年限、指标和项目归属，保留旧版本。
